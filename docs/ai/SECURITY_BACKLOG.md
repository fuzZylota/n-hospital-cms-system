### SEC-003 — current account status and stale role

- **SEC-003A / locally implemented, high confidence:** `main/main.go` orders `JWTMiddleware` before `HandleUserBanning`, then registers public, panel and backend routes. Previously `lib/lib.go` renewed the JWT before the status lookup; `HandleUserBanning` cleared a definitively inactive/missing user's cookie but still called `c.Next()`, and `userstatus/decision.go` treated lookup errors as permission to continue. A pre-fix in-memory HTTP test (`lib/auth_status_test.go`) showed inactive, deleted and lookup-error requests each reached a protected `/panel` handler and returned 200. Now the ban middleware returns 401 and clears only a definitively inactive/missing account's cookie, or returns 503 without changing the cookie on lookup failure. `JWTMiddleware` writes a refreshed cookie only after a successful downstream response and preserves a cookie set by a login/logout handler. Anonymous public requests continue without a status lookup.
